# 安卓端界面重设计 — 设计方向（v0.1）

> 状态：**方向稿，待拍板**。本文只定方向和依据，不含最终 token 值与组件代码。
> 证据来源：2026-10-15 在**一加 Ace 3（Android 16 / 1264×2780 / dpr 3.5）**真机上
> 用 `adb screencap` + CDP `Runtime.evaluate` 实测，共拓 5 个界面。
> 界面代码范围：本 fork 新增的 `src/library/suites/netease/`（网易云手机版竖屏布局）。
>
> 功能结构（页面、路由、交互、命令面板入口）**一律不动**，本次只动表达层。

---

## 0. 一句话结论

骨架和主题层是好的，**但主题层之上没有系统**——字号、间距、层级、圆角都是每个页面各写各的，
所以五个页面共用一套结构却不共用一套视觉语言。其中**字体一项就是单点最大的问题**：
声明的是无衬线，实际渲染出来是衬线。

---

## 1. 实测证据

### 1.1 字体：声明 sans-serif，真机渲染衬线 ⚠️ 最高优先级

放大截图逐字确认：`音乐库`、`搜索歌单`、`专辑`、`CHU CHU`、`推荐/本地/专辑/远程/我的`
全部是**宋体/明朝体**（横细竖粗、三角形衬线末端）。

但 CDP 回读的声明是：

```
html / #root  font-family = -apple-system, BlinkMacSystemFont, "Segoe UI",
                          Roboto, "Helvetica Neue", "Noto Sans", Arial, sans-serif, …
#root > div  class = "… font-sans …"
```

- 全站 **0 个元素**的 computed `font-family` 含 `Folia Noto Serif SC`；
- `document.fonts` 显示 `Folia Noto Serif SC` **400 已 loaded**（weight 500 未加载）；
- `settings get system font_name` = `null`，设备**没有**改系统字体；
- 设备同时存在 `NotoSansCJK-Regular.ttc` 与 `NotoSerifCJK-Regular.ttc`。

**结论**：安卓端这套 UI **没有自带 webfont**，完全继承设备对 `sans-serif` 的解析结果，
而在这台机器上它解析成了衬线。所以这不是「配错了字体」，是**根本没锁字体**——
换一台设备、换一次系统字体设置，界面长相就会变。

> 附带发现：一份完整 CJK 衬线 webfont 已被加载进内存。若确认全 App 无处引用，
> 这是纯浪费的流量和内存，应一并处理。

### 1.2 字号：7 个档位挤在 10–16px，主次不分

| 用途 | 字号 | 字重 | 行高 | 比例 |
| --- | --- | --- | --- | --- |
| 页面标题 `音乐库` | **16** | 600 | 24 | 1.50 |
| 区块标题 `推荐歌单` | 14 | 600 | 20 | 1.43 |
| 快捷卡标题 `每日推荐` | 12 | 500 | 16 | 1.33 |
| 歌单卡标题 `今天从…` | **13** | 400 | 16.25 | 1.25 |
| 计数 `33 首` / `35 首` | 11 / 10 | 400 | 16.5 / 10 | 1.50 / 1.00 |
| 歌手名 `Pupi` | 11 | 400 | 13.75 | 1.25 |
| 底部 tab 标签 | 10 | 400 | **10** | **1.00** |

问题：

1. **页面标题只比卡片标题大 3px**（16 vs 13），主次几乎消失；
2. **同类信息两个字号**——计数有 11px 和 10px 两种写法；
3. **行高比值在 1.00 / 1.25 / 1.33 / 1.43 / 1.50 之间混用**，不是按字号档统一推导的；
4. **tab 标签行高 = 字号（10/10）**，中日文和假名有溢出裁切风险——这是实打实的 bug 级取值；
5. 字重只用了 400 / 500 / 600，其中 600 只落在 2 个元素上，没有强调级。

### 1.3 配色：占位色漏进了正文

正文/次要色在实测里出现了这一串：

```
rgb(27,52,51)   ← 正常正文
rgb(2,2,1)  rgb(1,2,2)  rgb(2,1,2)  rgb(1,3,1)   ← 彼此只差 1~2 个数值
rgba(70,112,105,0.55)   ← 次要
rgb(70,112,105)         ← 次要
rgb(21,150,102)         ← 强调
```

- 后四个近黑色来自 `neteaseTheme.ts` 的 `placeholderTint()`——它按歌名散列色相给**封面占位**
  生成颜色，现在**被当成了文字色**。它们本意是「没有封面时的色块」，不是正文。
- 次要文字用 `rgba(...,0.55)`，但同屏还出现 `0.85`、`0.6` 等透明度，同一语义多套写法。

底色阶梯（`bg / surface / elevated`）在浅色主题下三档色差只有 **3% 亮度**，
实际几乎看不出来——所以卡片没有边界，整页靠封面图本身区分区块。

### 1.4 间距：同一个页面里左右边距就有两种

实测容器 padding：

| 位置 | 类名 | 左右边距 |
| --- | --- | --- |
| 歌单栅格 | `px-4` | **16px** |
| 快捷卡栅格 | `px-4` | **16px** |
| 区块标题 | `px-4` | **16px** |
| 顶部标题栏 | `px-3` | **12px** |
| 搜索条 | `px-3` | **12px** |
| 底部栏容器 | `px-3 pb-2` | **12px** |

→ 同一个界面里 **16px 和 12px 混用**，左边缘对不齐。
间距全部来自 Tailwind 任意值（`pb-1.5`、`gap-2.5`、`pt-4`），**没有统一栅格**。
栅格内部也是 `gap-x-3`(12) 与 `gap-y-4`(16) 不成比例。

### 1.5 圆角与投影

- 全站 **`box-shadow` = 0 处**；
- 圆角只出现 `6px`、`8px` 和 `rounded-full` 三种，没有中间档；
- mini player 是一张白卡浮在列表上，与 tab bar 之间还留一道缝，
  两者**没有共同的层级语言**，看着像两个互不相干的浮层。

### 1.6 布局效率

底部 tab 栏（54px + 19.4px 手势区）+ mini player 合计约 **180px**，
占 794px 视口的 **23%**。竖屏下留给内容的空间偏少。

## 2. 设计方向（五条线）

### 方向 A — 视觉层级：从「没有主次」到「四级主导」

现状是所有东西都在 10–16px 里互相挤。方向是**明确四个主导级**，
级与级之间用 1.2 倍率拉开，并且**每级锁死字号 + 字重 + 行高**，不允许页面自行改写。

| 级别 | 承担 | 建议规格 |
| --- | --- | --- |
| L1 页面级 | 页面标题、大标题 | 24px / 700 |
| L2 区块级 | 分区标题、空状态标题 | 17px / 600 |
| L3 条目级 | 歌名、歌单名、艺人名 | 15px / 500 |
| L4 元信息 | 歌手、时长、计数、tab 标签 | 13px / 400 |

配套三条硬规则：

1. **元信息统一 13px**，计数不再出现 11px / 10px 两种写法；
2. **行高跟字号档走**，不跟组件走——L1/L2 给 1.3，L3/L4 给 1.45；
3. **底部区压缩**：tab 栏 54→50px，mini player 与 tab 栏合成**一个**底部堆栈
   （共享一条分隔线、共享圆角），省下的高度还给内容。

### 方向 B — 配色：把「6 个近似色」收成「1 条中性阶 + 1 个强调」

1. **中性阶定 5 档**（bg / surface / raised / border / 文字四级），每档**明确亮度差**，
   不再用 3% 这种肉眼不可见的变化；浅色主题最低档与底色至少差 6% 亮度。
2. **强调色收窄到三个场景**：选中态、正在播放标记、主按钮。
   **正文和标题永不使用强调色**。
3. **`placeholderTint()` 只能产出背景**，禁止流进文字色——
   这是 1.3 节那四个近黑色的直接来源。
4. 次要文字统一成 **实色**（不再用 0.55 / 0.85 多个透明度表达同一语义），
   用预先算好的实色值，明暗两套各一份。

### 方向 C — 字体体系：锁字体 + 建字阶（**单点收益最大**）

分两件事，缺一不可：

**C1 锁字体（解决 1.1）**
应用必须**自带一份确定的 webfont**，不再依赖设备对 `sans-serif` 的解析。
- 中文：思源黑体 / Noto Sans SC 子集；
- 拉丁与数字：与中文同族的配套西文字体，避免中西文混排的字重不匹配；
- 桌面端现有的衬线 webfont 与本次安卓改造解耦（另议，不在本文范围）。

**C2 建字阶（解决 1.2）**
按方向 A 的四级落地字阶表，配套：
- 数字用 `font-variant-numeric: tabular-nums`（时长、计数、序号现在会跳动）；
- 日文/假名的行高单独留余量（方向 A 第 2 条已覆盖 tab 标签的 10/10 问题）；
- 字重固定四档 400 / 500 / 600 / 700，明确谁可以用 700。

### 方向 D — 间距栅格：4pt 基准，屏幕边距锁 16

1. 引入 **4pt 基准**，所有间距只允许取 4 / 8 / 12 / 16 / 24 / 32；
2. **屏幕左右边距全局锁 16px**，消灭现在 12 / 16 混用导致的左边缘错位；
3. 纵向节奏锁 **8 的倍数**：区块间距 24、卡内间距 8；
4. 栅格间距统一为 **12**（现在是 `gap-x-3` / `gap-y-4` 不成比例）。

### 方向 E — 组件样式统一：三级高度 + 四档圆角

1. **定义三级高度，每级有明确表达**：

| 级别 | 用途 | 表达 |
| --- | --- | --- |
| L0 | 页面内容、栅格卡片 | 无边框，靠间距分组 |
| L1 | 列表项、输入框 | 1px 发丝边框 + 圆角 |
| L2 | mini player、浮层、下拉菜单 | 投影 + 圆角（现在全站 0 处投影） |

2. **圆角收 4 档**：8（小元素）/ 12（卡片）/ 16（大容器）/ full（胶囊与圆形按钮），
   消灭现在 6 / 8 / full 三档无序状态；
3. `neteaseParts.tsx` 里已有的 **13 个共享零件**逐个定规格（tab 栏、标题栏、搜索条、
   更多信息菜单、曲目序号、mini player、播放按钮、区块标题、空状态、折叠区、外壳），
   由零件统一发色，页面不再各写各的。

## 4. 待拍板

1. **字体性格**：走方向 C1 去衬线（现代、清晰、列表信息密度高），
   还是保留衬线但把衬线**自己锁进 webfont**（延续 Folia 的文学气质，但需接受 CJK 衬线在
   小字号下的可读性成本）？**这一条决定后续所有字号与行高的取值。**
2. 底部 mini player 是否接受**与 tab 栏合并**（会改变现有交互手感，属结构级微调）。
3. 详细 token 表与逐组件规格是否在方向确认后**单独出一版**。
